## Что здесь

В данном дз, работа построена на основе клиентов подписки ПРАЙМ и их данных (о подписках, платежах, тарифах, каналах привлечения и тд). Эти данные используются для построения клиентской витрины, где зерно - "одна строка = один клиент". В работе проверяется отсутствие двойного счета по ключевым метрикам.

## Как запустить

Нужны [Git](https://git-scm.com/) и [uv](https://docs.astral.sh/uv/).
Python отдельно ставить не нужно — его поставит uv.

```bash
git clone git@github.com:ВАШ_ЛОГИН/prime-monitor.git
cd prime-monitor
uv sync
```

Доступ к учебной базе выдаёт бот курса по команде `/db`. Полученную строку
подключения кладём в `.env`:

```bash
cp .env.example .env
# и вписать в .env строку из бота
```

Проверка, что всё встало:

```bash
uv run python -c "from prime.config import get_engine; print(get_engine().connect().execute(__import__('sqlalchemy').text('select current_user')).scalar())"
```

Запуск JupyterLab:

```bash
uv run jupyter lab
```

## Что здесь считается

метрики notebooks/hw2.ipynb:

1. Контрольное число ДЕНЬГИ — `revenue`
   - сумма `amount` по успешным платежам (`status == "success"`);
   - используется как контроль общей выручки до сборки витрины.

2. Подписки без платежа — `no_payment`
   - количество подписок сегмента без единого успешного платежа;
   - такие подписки сохраняются после `left merge` и имеют пропуск в `n_payments`.

3. Платящие владельцы — `payers`
   - количество уникальных `owner_client_id`, которые совершили хотя бы один успешный платёж.

4. Выручка без канала — `no_channel`
   - сумма успешной выручки клиентов, у которых отсутствует `acquisition_channel`;
   - позволяет не потерять эту выручку при группировке `by_channel`.

5. Средний доход с платящего клиента (ARPPU) — `arppu`
   - для каждого владельца считаются `n_payments` и `paid`;
   - `arppu` = сумма успешной выручки / количество платящих клиентов (`paying`).

6. Выручка по цене справочника — `extended`
   - сумма `monthly_fee` тарифа «Расширенный» по цене, действующей на момент платежа;
   - для сопоставления используются исправленный справочник `ref_fixed` и строки платежей с найденной ценой `priced`.

7. Клиенты выше среднего по своему каналу — `above`
   - для каждого платящего клиента считается `paid`;
   - `channel_avg` — средний `paid` клиентов его `acquisition_channel`;
   - `above` — количество клиентов, у которых `paid > channel_avg`.

8. Выручка по месяцам и тарифам — `by_month`, `april_to_march`
   - `by_month` — таблица «месяц × тариф» с суммой `amount`;
   - `april_to_march` — выручка тарифа «Базовый» в апреле как процент от мартовской.

9. Пользователи ПРАЙМ — `uses_prime`
   - клиент считается пользователем, если он владеет подпиской или участвует хотя бы в одной чужой;
   - количество владений хранится в `n_owned`, количество участий — в `n_memberships`;
   - один клиент считается один раз независимо от числа подписок.

10. Люди на подписке — `share_slots`
   - для каждой подписки считается владелец плюс количество подключённых участников;
   - считается среднее количество людей на одну подписку;
   - `share_slots` задаёт максимальное число подключаемых участников;
   - отдельно считается количество подписок, заполненных до допустимого предела.

11. Стоимость привлечения клиента (CAC) — `cac`
   - `cac` для канала и месяца = `spend` / `registrations`;
   - CAC рассчитывается на зерне «канал × месяц», а затем присваивается клиенту по его каналу и месяцу регистрации;
   - считается средний CAC клиентов сегмента и количество клиентов без определённого CAC.

12. Лучшие регионы канала — `region_code`
   - успешная выручка группируется по `acquisition_channel` и `region_code`;
   - в каждом канале определяются три региона с наибольшей выручкой;
   - итоговый ответ содержит три `region_code` самого доходного канала.

13. Клиентская витрина — `mart`
   - зерно витрины: одна строка = один `client_id`;
   - основные поля: `acquisition_channel`, `region_code`, `subscription_id`, `tariff_id`, `n_payments`, `paid`, `n_memberships`, `uses_prime`;
   - `protocol` хранит результаты проверок каждого соединения;
   - контроль ЗЕРНО: количество строк = количеству уникальных `client_id`;
   - контроль ДЕНЬГИ: `money_mart` = `money_control`;
   - контроль ЛЮДИ: `people_mart` = `people_control`;
   - `answer_13` возвращает итог проверки протокола.
