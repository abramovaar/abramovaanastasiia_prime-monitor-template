## Что здесь

notebooks/hw1.ipynb отвечает за анализ моего участка ПРАЙМ (срез данных по таблице service_usage, в сегменте mobile. рассматриваемый период: с 2025-06-01 до 2025-06-30).

в заданиях 1-8, я считала количество строк, успешные сессии, корректные (ok = True) и некорректные (ok = False) события, длительность событий (value). также анализировала распределение активности по дням недели, рассматривала пики, "грязные" числа и взвешенную сумму, считала производные из этих данных.

в исследовании находится сравнение моей выборки из 1000 со всем сегментом, другими 20 тысячами, изменение value на 5%

## Как запустить

Нужны [Git](https://git-scm.com/) и [uv](https://docs.astral.sh/uv/).
Python отдельно ставить не нужно — его поставит uv.

```bash
git clone git@github.com:ВАШ_ЛОГИН/prime-monitor.git
cd prime-monitor
uv sync
```

Доступ к учебной базе выдаёт бот курса по команде `/db`. Полученную строку
подключения кладём в `.env`:

```bash
cp .env.example .env
# и вписать в .env строку из бота
```

Проверка, что всё встало:

```bash
uv run python -c "from prime.config import get_engine; print(get_engine().connect().execute(__import__('sqlalchemy').text('select current_user')).scalar())"
```

Запуск JupyterLab:

```bash
uv run jupyter lab
```

## Что здесь считается

метрики notebooks/hw1.ipynb:
1. Паспорт участка
   - общее количество строк;
   - количество строк с `ok=True`;
   - сумма `value` по строкам с `ok=True`;
   - количество различных дат.

2. Участники с разными исходами
   - количество уникальных `actor_id`, у которых есть и `ok=True`, и `ok=False`.

3. Сумма по дням недели
   - сумма `value` по успешным строкам отдельно для Mon–Sun.

4. Самый активный участник
   - `actor_id` с максимальным количеством строк `ok=True`;
   - количество его успешных событий.

5. Три пиковые даты
   - три даты с максимальной суммой `value` по строкам `ok=True`.

6. Момент накопления половины суммы
   - первый день, к которому накопленная сумма `value` достигла 50% общей успешной суммы;
   - порядковый номер этого дня.

7. Разбор грязных числовых данных
   - сумма значений из `RAW`, которые удалось преобразовать в числа;
   - количество отброшенных значений.

8. Взвешенная сумма
   - сумма `value` с поправочными коэффициентами по дням недели.

Дополнительные расчёты для анализа:

- количество и доля строк с `ok=False`;
- сумма `value` по строкам с `ok=False`;
- количество уникальных участников;
- среднее количество строк на одного участника;
- количество дат для каждого дня недели;
- средняя сумма `value` на одну дату по дням недели;
- количество участников, делящих первое место;
- дни недели для трёх пиковых дат;
- количество выходных среди пиковых дат;
- доля дней, за которую накопилась половина суммы;
- доля отброшенных значений из `RAW`;
- дни с коэффициентом по умолчанию `1.0`;
- процентное отличие взвешенной суммы от обычной.
